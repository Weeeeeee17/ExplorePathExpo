# v0.8.1 相容修正與測試報告

日期：2026-08-31。環境：Windows、Node 24.19.0、npm 11.17.0。

## 問題與修正

使用者啟動 v0.8 後，手機回報「Project is incompatible with this version of Expo Go」。原始套件為 SDK 57，但 iPhone App Store 版 Expo Go 支援 SDK 54。v0.8 雖通過 JavaScript／Hermes 匯出，未驗證商店版實機相容，原交付說明有疏漏。

本版對齊 Expo 54.0.37、RN 0.81.5、React 19.1.0，以及 Expo 原生模組矩陣；不透過 app.json 的 sdkVersion 偽裝版本。相簿恢復 SDK 54 入口，移除不適用的 sharing config plugin（仍保留分享 API），TypeScript 回到 5.9。Windows 啟動器新增版本、SDK、lockfile 雜湊檢查與 Metro 快取重建。

好友、組隊、任務、2D 占位場景、打卡及既有健康／足跡維持原邏輯。兩份 Supabase migration、儲存鍵與備份 v3 格式不變。不刪除手機資料、不使用付費簽署。

- `npx expo export --platform ios --output-dir dist-v081-release --clear`：成功匯出 1,202 個模組，Hermes bundle 約 3.97 MB。
- Windows 啟動與封裝腳本語法檢查通過，UTF-8 BOM 保留，避免 Windows PowerShell 中文解碼錯誤。

- 實際啟動 SDK 54 Metro（測試埠 8091），以 iOS manifest 請求取得 `runtimeVersion: exposdk:54.0.0`、App 0.8.1／SDK 54.0.0；開發用 iOS bundle 1,313 個模組編譯成功，測完已停止此測試伺服器。

- 封裝器直接檢查 ZIP 內 lockfile 的 0.8.1／SDK 54／RN 0.81.5，排除 node_modules、dist、.expo、.git、實際 .env 與 .npmrc，保留 .env.example。

以上不等同 iPhone 實機成功開啟，仍請依下方清單確認。

## 套件風險與限制

SDK 54 初次安裝 audit 為 17 項（9 high、8 moderate）；將 Expo Metro 使用的 PostCSS 限定為同主版本修補 8.5.26 後，為 **16 項：8 high、8 moderate、0 critical**。

剩餘根因為 Metro 的 image-size 影像解析阻斷服務風險、xcode 的 uuid 弱點及其相依鏈。npm 建議的 SDK 57 升級會重現這次不相容；沒有執行 `npm audit fix --force`，也未把不相容的主版本硬塞進依賴。

本版僅供可信任小群體開發測試：不把 Metro 暴露至公開網路、不使用公開 tunnel，不在建置流程處理不可信 ICNS／JXL／HEIF 素材或 Xcode 專案，測完停止伺服器。照片由手機 API 在本機處理，不是交給 Metro 掃描；但這不代表套件弱點已修好。正式公開前必須重新評估修補與 development build 路線。

來源：[Expo SDK 不相容說明](https://docs.expo.dev/troubleshooting/expo-go-version-mismatch/)、[SDK 54 支援範圍](https://docs.expo.dev/versions/v54.0.0/)、[SDK 54 模組矩陣](https://github.com/expo/expo/blob/sdk-54/packages/expo/bundledNativeModules.json)、[PostCSS 修補說明](https://github.com/postcss/postcss/security/advisories/GHSA-fxqj-rqcc-2cmp)。其餘弱點詳見 `npm audit` 即時結果；audit 不是安全認證。
